Vellen — What's new

Latest: version 1.0.32

Every version, what it changed, and what was wrong before it. Written plainly, on purpose: a notes app is something you trust with your thinking, and you should be able to see exactly what we fixed and when. Something not right? Write to admin@capitalcalcs.com, or use Settings → About → Report a problem inside Vellen.

Version 1.0.32

Everything below comes from the first full unattended round of hands-on
passes (14 Sep 2026: iOS, Android, reviewer, sync, local AI, big vault,
files, accessibility — 61 findings, reports/passes/2026-09-14-*.md).

  • A note that isn't UTF-8 text can no longer be destroyed by typing in it. A .md in an old code page (the kind an imported Windows vault is full of) showed � for every accented letter, and the first autosave wrote those replacement characters over the original bytes for good, with no version kept. Such a note now opens read-only with a banner saying why; Edit anyway keeps a byte-for-byte copy under .history/raw/ first.
  • Reinstalling on Android and choosing the same folder opens your notes again instead of creating an empty "My notes (1)" beside them — which showed the welcome note and none of your writing, with nothing to say why. The drawer's item is now "Open a folder as a notes folder…".
  • Local AI works from the built Android app. Requests to a local server carried the app's own origin, which Ollama refuses (403) — and the refusal was reported as "can't reach the server". Local requests now send no origin, and a server that answers no is described as refusing, with the status.
  • Diagnostics no longer leak a word of a note's name. A three-word file name in an error left its middle word between the redaction markers; the whole path goes now, spaces and all.
  • Android's Back button closes what is on top first: an open ⋯ menu or the drawer, before anything behind them moves — and it keeps working after the app has been sent to the background and brought back (every press used to quit the app from then on).
  • iPhone and iPad: the app no longer scrolls out from under the status bar on a swipe, and tapping a field no longer zooms the page and leaves it zoomed (the "Connect" button, the encryption unlock screen and the note-details ✕ all went off-screen that way). Fields keep at least 16 px text on touch screens; pinch-zoom is unchanged.
  • Menus fit the phone. The whiteboard card menu ran past the right edge with "Remove from board (the note itself is untouched)" cut at "unto…"; menus now wrap within the screen.
  • A folder renamed or moved in Finder is followed. Its notes used to stay listed under the old name, unopenable ("may still be downloading"), and then appear twice once anything touched them. A note renamed in Finder while open keeps its tab too, with a notice, instead of the tab closing without a word.
  • Sync says the right thing after a delete/edit clash. "1 needs your review (copies saved)" over a note that simply came back — nothing to review, no copy saved — is now "1 note you deleted came back, edited elsewhere"; that sync shows in the recent list rather than being filed as quiet; and the conflict copy an edit/edit clash creates is uploaded by the same sync, not the next one.
  • Vellen's AI can answer "what format are my notes in, and where do they live?" A Help topic, Where your notes are stored — plain Markdown files, now exists for it to read (it used to search the web and conclude Vellen might not exist).
  • Branch → note never makes a second note with an existing title (which made every [[link]] to it ambiguous); it numbers the new one and says so.
  • Boards say when notes are off the columns: "3 without a status →" beside the count, linking to the "No status" column — a new board over a folder read "4 notes" above three empty columns with the fourth column off the edge of an iPad.
  • Calendar cells show a few chips and "+N more" instead of crushing eighteen items into 6-pixel slivers.
  • The graph on a phone shows its screen and progress at once rather than a blank page for the 25 seconds a 3,000-note graph took to build, and the finished layout is framed in the viewport instead of a corner. Tidy tree says when a tree is taller than the screen and starts at its top.
  • Touch targets meet the 44-point floor on phones and tablets — the note action row (Delete no longer one of five identical circles), the calendar's month arrows, the conflict banner's buttons (which now wrap instead of running off the screen), the [[ note picker, AI provider chips, the whiteboard toolbar; checkboxes grow with the text size.
  • Phone header names the view — Tasks, Graph, Calendar — instead of the note you left; search excerpts read as prose, not Markdown source; Help paragraphs re-flow on a phone; the whiteboard's gesture hint wraps instead of stopping mid-word; Android's first frame is dark, not white.
  • Local AI wording. The green headline names the model that is actually answering (LM Studio uses whatever it has loaded); "Refresh model list" works on LM Studio; the row under an amber "couldn't be verified" no longer says "is connected"; a settled model name is said once; small models no longer echo "[Note]" from the citation example.
  • Screen readers: the notes list is a named tree that announces the note you arrow to; the note editor is "Note text"; every property field is named by its property and every Remove says what it removes; the Settings, note-panel and saved-view tab lists move with the arrow keys and take one Tab stop; whiteboard and board cards are reachable by keyboard; a note's tab is named for the note alone; the four sidebar "+" buttons say what they add; "Links (2)".
  • Store screen: "Vellen couldn't reach the App Store just now — your trial is unaffected" replaces "The App Store record: couldn't be read just now."; the unlock covers "your iPhone, iPad and Mac" rather than "this store's ecosystem"; encryption settings say "this device" on a phone; a web-search answer's continuation no longer runs into the previous sentence.
  • Open a particular folder at launch — open -a Vellen --args --vault <folder> on a Mac (or --vault=<folder>) opens that folder instead of the remembered one. For scripted and automated use; it becomes the remembered folder like any other.
  • Pass infrastructure: the preflight checks the Anthropic key is live, refuses an installed app too old for --vault, and reads reachability by status; a round builds the Mac bundle from HEAD first and can be resumed; each pass frees port 1420, restarts the Simulator app, boots the named devices and tears everything down after; the Android pass's spurious conflict banner (a resume rescan reading a half-written file) is fixed by never reading a note while our own write is in flight.

Version 1.0.31

  • Vellen follows the system text size on phones and tablets. The size set under Accessibility → Display & Text Size now scales the sidebar, menus, panels and note text (up to about 1.6×, so every screen stays usable at the largest settings). Until now the app rendered pixel-for-pixel the same at the largest accessibility size as at the default — the one app on the phone that didn't answer. Settings → Appearance has a switch to turn it off; Vellen's own text-size buttons still work on top.
  • Screen readers and the keyboard. Task checkboxes in a note now carry their task's words as their name ("Task: Buy milk") instead of a bare "checkbox", and sit outside the Tab order so the app's own controls come first. The formatting toolbar is one Tab stop with the arrow keys moving inside it, as its role has always promised; the two "H" and two "A" buttons have distinct names (Heading / Highlight, Smaller text / Larger text). The properties panel's "Add property" field has a proper label.

Version 1.0.30

  • An outside edit that lands right after an autosave is no longer missed. For two seconds after Vellen saved a note it treated any change to that file as the echo of its own write and ignored it — so a line appended by another program (or another device's sync) inside that window never reached the editor, no banner appeared, and the next keystrokes were refused by the safety check with nothing on screen to say why. The file's content now decides what is Vellen's own: an outside change shows at once on a clean note and raises the "changed outside this window" banner on one with unsaved typing. A file that vanishes under unsaved typing is likewise noticed whatever the clock says, and the words are kept. Failed-create notices name the note without its extension.
  • Opening a big vault: the folder listing is one round trip. The timings shipped in v1.0.29 answered the question they were built for: of a 3,000-note vault's 2.4 s open, 1.07 s was "scanning the folder" — not disk time (27 ms in one process) but three thousand crossings of the webview boundary, one per note, to read its date and size. The app now walks the vault natively and answers once; the old walk stays as the fallback. A second line in the timings, "launch: webview start → open vault begins", now separates app start-up from the vault open, since the 5.9 s the pass saw from launch held only 2.4 s of the latter.

Version 1.0.29

  • The graph settles in about half the time on a big vault. A 3,000-note, 15,000-link vault took seven seconds to arrange. The physics is unchanged; its bookkeeping was the cost — a fresh hash map of neighbour buckets every tick and every pair visited twice. It now sorts nodes into a grid of reused typed arrays and sees each pair once, with a tighter neighbourhood that still covers the spacing unlinked notes settle at; and the dots are drawn as one shape rather than three thousand. Measured: 8.7 → 4.4 ms a step.
  • Vellen now times its own slow phases, and the diagnostics say so. Opening a vault (each step and the total), arranging the graph, a search, collecting tasks and Tidy tree each record how long they took; Settings → About → Copy diagnostics includes a "Timings (this session)" section. A hands-on pass spent a day trying to time a release build from outside with screenshots and got numbers that were plausible and wrong; this is the answer from inside.
  • Big-vault housekeeping. Opening a note re-rendered every row of the sidebar (600 ms at 3,000 notes — a row now redraws only when the change names it or something below it); the hover-only delete button is created only for the hovered row (a third of the sidebar's DOM); and the indexing progress line updates ten times a second instead of once per fifty files, which on a cached open re-rendered the app sixty times for a line nobody could see.

Version 1.0.28

  • After unlocking an encrypted notes folder, background sync now actually resumes. v1.0.27's fix for the silent phone cleared the banner and pulled the other device's edits the moment you entered the passphrase — and then stopped again: the background timer parked by the refusal was never restarted, so a note written on the phone sat there until a relaunch or Sync now. Found on a real iPhone within an hour of shipping, on the exact test written to close it. Now the timer restarts whenever a sync succeeds while it is parked; the test goes on to edit a note after the unlock and watches it reach Drive, sealed, by itself.
  • Rename a note from its row. A new note is "Untitled" until you name it, and on a phone the row's long-press menu offered everything but a rename — the only way was ⋯ → Rename… on the open note. Right-click (or long-press) a note or whiteboard in the list → Rename… now turns the row into a name box; F2 on a focused row does the same. It asks first when other notes link to it, like the editor's pencil.
  • Local AI: what Settings says is now what is true. A hands-on pass against Ollama, LM Studio and a few impostors turned up nine ways the AI panel and Settings misreported the state of a local server:
    • A green "AI is connected" survived a model that didn't exist, a server that was down, and a web page that was not an AI at all. A check that doesn't get a proper answer is now an amber "set up, but couldn't be verified just now" with the reason under it — never green.
    • Connecting to an address that answers with a web page (a router's admin page, say) went green, and asking it said "the AI returned an empty response" — sending you to change models. It now says the address answered but not like an AI server, and names where Ollama and LM Studio usually listen.
    • A stopped server showed a raw transport string ("error sending request for url…") where the friendly sentence already existed; the sentence now says "Couldn't reach the local AI server at …" with a step for Ollama and LM Studio, since the field invites both.
    • After a failed model, picking a different one left the old complaint under the new name until you pressed Test connection; changing the model now re-checks at once.
    • LM Studio answers an unknown model name with whatever it has loaded, silently; Settings now says "the server answered as X, not Y".
    • An answer whose connection died mid-sentence was presented as finished, with Save as note offered. It is now marked Cut off, the Save button says so, and Retry is suggested.
    • A doubled full stop in the Settings detail line; "add a provider key" under a field that takes an address. Help's troubleshooting list now describes these messages, and names the whiteboard's fold menu items (the AI had invented an "Unfold" entry because Help said "the same choice" without naming it).

Version 1.0.27

  • A device whose notes folder was just encrypted from another device no longer falls silent. A two-device pass found the iPhone quietly stopped syncing — in both directions — the moment the Mac turned encryption on: it fetched the keyring, refused (correctly) to sync without the passphrase, and then said nothing at all. The refusal now shows as a banner where you are, with an "Open encryption settings" button that lands on the passphrase box; Settings → Sync carries the same sentence; Recent sync activity records "Paused — needs your passphrase" instead of a history that simply stops; and background sync waits for the unlock rather than retrying every few minutes. Once unlocked, sync resumes on its own. The sentence itself now names the screen ("Settings → Encryption") rather than telling you to scroll down to a section that moved.
  • A note you deleted that comes back — because another device edited it after you deleted it — now says so. The edit surviving is the rule and stays; what was missing was any word about it. A short notice names the note and the reason, and Recent sync activity lists it as "came back … edited elsewhere after you deleted it" rather than as a new arrival. An edit/delete clash no longer counts as "1 to resolve" in that history either — there is no conflict copy to resolve.
  • The "Get your notes" list labels its count honestly. "10 items" beside a vault the Mac calls "14 notes · 1 whiteboard" looked like a disagreement; it is a count of the folder's top-level entries, and now says so.

Version 1.0.26

  • Three things a hands-on pass through the iPhone build turned up. The whiteboard's fold badge and connection dots shrank with the board's zoom — on a map just laid out, the badge was about 7 points across, well under a fingertip; they now hold their size on screen whatever the zoom (and are drawn a little larger on phones, with a wider tap area). "Map from a note's outline" placed the new tree from a fixed point, on top of whatever was already on the board; it now starts below the lowest existing card. And the phone's hint bar still said "long-press a card: remove" when long-press has become the phone's menu — open, branch, fold, remove; it says so now.
  • Maintenance note. The iOS row of the webview matrix records the pass: WKWebView on iOS 26.5 / Xcode 26.6, editor, whiteboard and Tasks all behaving.
  • Five more from the same kind of pass, on Android. The Tasks view's checkbox was a 15-pixel target on a row that opens the note, so a near-miss threw you out of the list instead of ticking the task; it now has a generous tap area around it (larger still on phones) that ticks the task. Right-click and long-press menus on phones and tablets have 44-point rows, and the destructive item is set off from the rest by a rule and a gap. A map made from a note's outline is now moved clear of existing cards as a whole — the earlier fix placed only the root, and a tree's upper branches fanned back up over the old cards. When a local AI server can't be reached or refuses the request, Settings now says that, instead of claiming a key has expired (a local server has no key). And the Tasks view shows a task's words rather than its markdown — **bold**, ==highlight== and links are rendered as text, while the note keeps its marks.
  • Straight quotes stay straight. On a Mac, typing between two quotes in a note — 'v' — could have macOS swap them for curly ones, and the cursor then landed outside the opening quote so the rest of the word arrived in the wrong place (ellen123‘v’); a command copied from that note broke in the terminal. Vellen now declines the system's smart-quote and similar substitutions while Auto-correct is off, and always inside code, fenced or inline. Spelling underlines are unaffected.
  • What an App Store reviewer sees, fixed at the source. A hands-on pass along the review notes on a fresh iPhone found the app asking the App Store about the trial — and, on opening the folder, showing the $0.00 trial sheet — before the licence had been accepted, with the sheet's explanation hidden under the licence text. Nothing now talks to the store, and no folder opens, until "I Agree". The phone's ⋯ menu ran off the bottom of the screen with Settings out of sight and no hint that it scrolled; it now fits the screen when it can and shows "⌄ more" when it can't. The AI sheet's title row keeps clear of the status bar, and its ✕ is finger-sized. And a phone no longer says your notes are "on your computer".

Version 1.0.25

  • Help catches up with the whiteboard. The whiteboard topic now says that Tidy tree gives labelled arrows a wider gap, and points at the Color menu (not swatches) for colouring a selection; "All keyboard shortcuts" gains a whiteboard table — Tab, Enter, ⌘/Ctrl+Enter, Shift+Tab, − and +, Shift+click and Shift+drag, Delete, Escape. The split-panes row of that table had been showing its backslash twice.
  • A note's outline becomes a map, and a map becomes notes. On the whiteboard, + Add → Map from a note's outline… reads a note's headings and bullet lists and lays them out as a tree — the title as the root, headings as branches, bullets as cards, nested as the note nests; prose and code are left behind. Going the other way, right-click (long-press on a phone) a card with cards branching off it: Branch → outline note writes the branch as a note beside the board (heading plus nested bullets — mapping it again gives the same tree back); Branch → checklist note does the same with - [ ] on every line, so the Tasks view picks them up at once; and Branch → a note per card makes a folder named after the card with one note per card below it, each carrying status: To do, a title from its first line and a link to its parent — and turns those cards into note cards, so a Kanban board on that folder, grouped by status, shows the branch as a pipeline while the map stays in step with it.
  • A note card no longer says its title twice. A card showing a note whose first heading only repeats the file name now shows that title once, in the card's title bar; a heading that says something different is kept. Frontmatter never shows on a card. The Tasks and Boards Help topics now point at the whiteboard's Branch → … commands as a way in.
  • A mapped note is the root of its map. "Map from a note's outline" now puts the note itself at the root as a note card, so the board shows under the note's "On whiteboards" and a double-click on the root opens the note. And a selected card's four connection dots are now drawn whole on its edges rather than clipped to half-moons.

Version 1.0.24

  • Whiteboard branches fold, and cards select in groups. A card with cards branching off it now carries a small − in its corner: click it (or press − with the card selected) and everything downstream tucks away behind a +N badge that says how many are hidden; click again, or press +, to bring them back. Right-click (long-press on a phone) offers the same. A folded card drags its hidden branch along with it, and Tidy tree treats it as a single card, so a big map can be worked one limb at a time. Nothing is removed from the file to fold it — the card simply gains collapsed: true, which any other JSON Canvas app ignores and shows in full. And on a computer, Shift+click adds cards to the selection, Shift+drag on empty space lassoes them, and the whole selection then moves, colors, or deletes together (the Delete button counts them). The in-app Help's whiteboard topic covers both.
  • Drag a whiteboard card onto another to move its branch there. The target card lights up as you hover; let go and the dragged card becomes its child — the arrow is re-pointed (label and colour kept), the card lines up as the new parent's last child, and everything below it comes along in the same shape. A card set down beside another just moves, as before. A card can't be dropped on itself or on anything below it, since that would tie the tree into a loop, and a folded target unfolds so you can see what you did.
  • Tidy tree leaves room for arrow labels. A level whose arrows carry labels is now set far enough right that the widest label sits in clear space between the cards, measured in the font it is drawn in — "if both viable" was being squeezed into the standard gap and half hidden behind the cards on either side. Levels without labels keep the usual spacing, and the columns stay straight. Arrow labels on every board also now sit just above the line instead of on it, with a slightly wider halo, so the line never runs through the words.
  • The whiteboard toolbar fits the window. With a card selected it held twenty-one things — and in anything short of a full-screen window the colour swatches, and whatever came after them, were cut off with no way to reach them. The four "+ …" buttons are now one + Add menu (Text card, Note from your vault, Web link, Group) and the eight swatches one Color menu whose button shows the selection's current colour as a dot. And the row now measures itself: whatever still doesn't fit folds into a ⋯ menu at the right end, least-missed tools first (Delete is the last to go), and comes back as the window widens. Every tool is one tap away at any width. A phone keeps its scrolling row.

Version 1.0.23

  • The whiteboard is now a mind map you can type. Select a card and press Tab: a new card branches off it, already placed to the right, already joined by an arrow, already open for typing. Enter adds a card beside it on the same branch. Both work mid-sentence inside a card's text too (Tab, and ⌘/Ctrl+Enter), and Shift+Tab climbs to the parent — so a brainstorm runs as fast as you can think. When it gets messy, Tidy tree lays the whole tree out left to right in clean columns with every parent centred on its branches, keeping the root where you put it and leaving everything else alone. Nothing about the file changed: a tree is ordinary cards and ordinary arrows, so the board still opens anywhere a JSON Canvas does, and a tree you drew by hand tidies the same way. + Child, + Sibling and Tidy tree are buttons too, for a phone or a tablet. And reopening a card for editing now puts the cursor at the end of its text, where you almost always want it.
  • Three things an end-of-week read of the week's own fixes turned up. A local AI server that answers the model-list request with a polite "unknown endpoint" (LM Studio does) was being read as "no models installed" and refused; it is now left to answer for itself. A Drive listing whose connection drops after the headers arrive was still being read as an empty Drive — the one shape the 9 Sep fix hadn't covered — and the two root-folder lookups that could have created a second "Vellen" folder on an incomplete answer now go through the same checks as every other listing. And the model field in Settings → AI could be overwritten by the local provider's background check while another provider's panel was open, or while you were typing a name.
  • Help no longer contradicts itself about the web, and the AI's chapter picker ignores bold sentences (only bold names count as a chapter's subjects).
  • The AI now finds features by their names, not just their chapter titles. Asked "what is the clipper?", it answered that Vellen has no clipper — the manual's chapter is called "Saving web pages", and a word that appeared only inside a chapter counted for almost nothing when choosing what the AI gets to read. Now a word the manual says rarely and repeatedly, or names in bold, weighs as much as a chapter title, so "callout", "backlink", "font", "quick capture" and the clipper reach their chapters; and a long word no longer matches a short one it merely begins with ("backlink" was matching every chapter that said "back"). Help also now names backlinks and the outline in so many words.

Version 1.0.22

  • "Qwen 3" finds the Qwen 3 you actually pulled. Help says to run "ollama pull qwen3:8b"; the model chip said "Qwen 3" and asked Ollama for "qwen3"; to Ollama those are different names, so the answer was "404: model 'qwen3' not found" under a green "AI is connected". Vellen now asks Ollama what it has before it asks it anything else, and a family name settles on the installed tag — the chip shows the name that answers. A name nothing installed answers to is refused up front, with the list of what is installed and where to pick from it, instead of by the server with a bare 404.
  • Local AI works again. Settings said "AI is connected · Local (Ollama)" and the chat said "Couldn't reach the AI provider. Check your internet connection" — while the model was running on the same machine. Vellen's own network permission was the culprit: it allowed "any http address", and the rule it used silently meant "any http address on the default port". Every cloud provider sits on the default port and was fine; Ollama sits on 11434 and was refused, and a model on another computer at home (the Help's own example) would have been refused the same way. The permission now says what was meant. A test now evaluates the app's real permission file against the real addresses — so it can't drift back.
  • A local model that can't be reached is blamed on the right thing. "Check your internet connection" was the one message for every provider, wrong for the one that doesn't use the internet. The message now names the address it tried and asks whether Ollama is running there; and if Vellen's own permissions ever refuse an address again, it says that's an app bug and where to report it, instead of sending you to look at the Wi-Fi.
  • Sync is now tested the way it runs. Every earlier test of syncing stopped at the edge of Google Drive, because the test harness had no Drive to talk to. It has one now — a small, faithful Drive that lives inside the test page, with real checksums — and seven end-to-end scenarios run the actual sync code against it: the first sync on a fresh account, a note edited elsewhere arriving while one edited here goes up, "already up to date", deletions from another device (asked first; Keep keeps), a note changed on both sides keeping both, and a Drive folder that really was emptied being refused with the notes untouched. Nothing in the app changed; what changed is how much of it a regression can hide behind.

Version 1.0.21

  • What's new, on the website. Every release note from this file is now published at vellen.capitalcalcs.com/changelog.html, in the same words, with the release date — so you can see what changed, and what was wrong before it, without opening the app.
  • "Your Drive copy looked empty" is no longer said about a Drive that isn't. A Windows machine reported that sync had protected its notes because the Drive copy looked empty — while the Drive copy was intact. Two things could make Drive's file list come back as nothing without Drive ever saying so: a "successful" reply that wasn't Drive at all (a hotel or airport Wi-Fi sign-in page, a proxy) used to be read as an empty list, and Drive's own "this search was incomplete" flag was ignored. Both now stop the sync with a plain sentence — "Google Drive couldn't be read properly — a Wi-Fi sign-in page or a proxy may be in the way" — and nothing is compared, so nothing is judged. The same sign-in page at token-refresh time no longer reads as "your Google sign-in has expired" either. The protection message itself now says the Drive copy may simply have been unreadable just now, and to look before rebuilding.
  • Help explains inline code. The formatting list said backticks make "inline code" and left it there. It now says what that's for — a file name, a shortcut, a menu path, an exact phrase, anything to be read exactly as written — and that everything inside is taken literally, which is how to mention a piece of Markdown without triggering it.

Version 1.0.20

  • Selecting a paragraph no longer paints two overlapping blocks. The line you're on has a faint tint that stops at the text; a selection across a wrapped paragraph is drawn the way every editor draws it, out to the edges of the writing area. Together they made a stepped block in two shades. While anything is selected, the selection is now the only highlight; the line tint returns when you click or move on.
  • Owners are never asked to register a trial. After updating on an iPhone that had already bought the unlock, a notice said the 14-day trial had been registered with the App Store — while About correctly showed the licence as owned. At launch the app asks the store and opens your last folder at the same time; when the folder won the race, the trial registration ran before the store had said "licensed". It now waits for the store's answer first (bounded, so an unreachable store still can't block a real trial), and the "registered" notice is only ever shown to someone actually on a trial.
  • New notes can take their folder's shape. A folder of like notes — every application, every project — tends to share the same properties, and a new note there used to start empty: open a neighbour, copy the names, blank the values. Now, when the other notes in a note's folder share properties it lacks, the Properties panel offers Add this folder's properties (3). One click adds the names with blank values — a checkbox unticked, a list empty — and never copies a value or touches one you already have; it adds only what's missing, so a note you started by hand catches up too. It reads only the notes beside this one (never a subfolder's or another folder's), and a folder with a table or board offers that table's columns. Never automatic: a note that should have no properties ignores it. Also in the command palette.

Version 1.0.19

  • Edit ▸ Select All selects the note, not the whole app. On a Mac, picking Select All from the menu bar lit up everything — sidebar, tabs, panels and note together — because the menu item was the system's own action, aimed at the window rather than at what you were editing (⌘A on the keyboard never did this; the editor handles that itself). The item is now Vellen's: it selects all of the note under the cursor, or the text field you're typing in, or a whiteboard card's text — and with nothing focused, it selects nothing at all.
  • The calendar emoji is gone from previews too. A task's due date is written in the file as 📅 2026-10-24, and on Apple devices that emoji draws a calendar page reading "JUL 17" — a second, wrong date beside the real one. The editor has hidden it behind the app's own icon since 30 Aug, but linked mentions, search results and the published site's search still showed it. Previews now read "due 2026-10-24"; rendered notes — hover previews, embeds, whiteboard cards, exported pages and websites — draw the same icon the editor does. The file is unchanged.

Version 1.0.18

  • The report that arrives after the restart. Diagnostics used to live only in memory, so a report made after reopening the app said "no errors recorded this session" — precisely when there was most to say. The last 60 events now carry across launches (labelled as an earlier session's), every message and stack trace is stripped of file paths before it is recorded rather than at one caller, and a save that fails while the app is quitting or closing is written down instead of being swallowed. Help's description of the report now matches it: the only path it shows is your notes folder's own location.

Version 0.1.53

  • The program is now actually called Vellen. The executable was note-app.exe — the old internal project name — so Task Manager (and any security software looking over your shoulder) showed a program called "note-app" for an app called Vellen. It's now Vellen.exe. This mismatch is also what made the installer hang below: the installer was told to close "Vellen.exe", a program that never existed.
  • Windows installer no longer hangs when Vellen is open. Installing over a running copy stalled at "Validating install" — sometimes uncancellably. The installer was told to close Vellen.exe, but that program doesn't exist: "Vellen" is the product name, while the actual executable is note-app.exe (named after the Rust package). So the close step reported "process not found" and quietly did nothing, leaving the app holding its files. It now closes the real process — and runs in the user's own session, where it can actually see it — so upgrading over a running Vellen completes on its own.

Version 0.1.52

  • Share a note as a single file that opens anywhere. The share menu's first action is now "Share as a file": it turns the open note into one polished, self-contained web-page file — styling, images, and diagrams baked in, and ![[embedded notes]] (including #section and #^block embeds) expanded into place so the document reads complete instead of showing raw syntax. It opens on any computer with no internet and nothing to install. After saving, the file is revealed in Finder/Explorer ready to drag into an email or message. (This replaces the old "Export as web page" item, which saved the file silently and left embeds as unrendered ![[...]] text.)
  • Quick capture — a global hotkey for fleeting thoughts. Press ⌘⌥N (Mac) / Ctrl+Alt+N (Windows/Linux) from anywhere — another app, mid-task — and a small always-on-top box appears (Vellen just has to be running). Type, hit Enter, and it's filed as a new note in Inbox/, named from its first line, without touching the note you had open. Esc dismisses without saving. The capture window is feather-light: it loads none of the vault machinery, so it opens instantly and can't disturb sync or the editor. Desktop only for now (mobile capture arrives with share-sheet support); the hotkey is fixed in this first version, with rebinding planned.
  • Block embeds — transclusion down to a single paragraph. End any line with a space and ^some-id, and ![[Note#^some-id]] embeds just that piece: a tagged paragraph brings its whole paragraph, a tagged list item brings its sub-items, and a tagged heading brings its full section. Block refs chain and mix with section embeds (![[Note#Intro#^price]]) and render in the order listed. The ^id markers are addressing, not content — they're stripped from every rendered card (including section embeds that pass over tagged lines), and renaming the source note keeps #^id chains intact. Embed cards are also now titled with the note's name (what the ![[...]] addresses) instead of its first H1 — a note file called "Test 3" whose first heading happened to be "# Heading 1" used to label all its embeds "Heading 1".
  • The graph button works from any view now. Clicking the graph icon while on the Tasks view (or a board) used to take you back to the note instead of the graph — you had to click it twice. The toggle only knew how to switch from the editor; now it opens the graph from wherever you are, and clicking it again on the graph returns you to the note. Same fix for the ⌘G shortcut and the command-palette entry.

  • You can now drag whole folders to reorganize — including image-only ones. Folders are now draggable: drop one onto another folder (or the "notes" header to move it to the root) and it moves with everything inside it.   • Vellen now checks your AI key actually works. Settings used to show "AI is connected" the moment you saved a key — even if the key was expired or wrong — so you'd only find out it was dead when a prompt failed. Now Vellen verifies the key with a tiny test request when you paste it and whenever you open Settings: it shows "connected" only when the key genuinely works, flags an expired or rejected key with a clear warning (and lets you paste a replacement right there), and adds a "Test key" button to re-check on demand. And if a prompt ever is rejected mid-use, the error now says plainly that the key was rejected and to update it, instead of failing cryptically.

Version 0.1.50

  • Section embeds — pull in just part of a note. ![[Note]] embeds a whole note; now ![[Note#Heading]] embeds only the content directly under that heading (stopping at the next heading of any level, so subheadings below aren't pulled in). You can also chain headings to pull in several at once — ![[Note#Heading 3#Heading 5]] embeds just those two sections, in the order you list them. The embed card stays live and updates when the source changes, and renaming the source keeps the #heading chain intact. Missing headings show a clear "section not found" note. (Block-level embeds — #^id — aren't supported yet and fall back to the whole note.)
  • Windows installer actually closes a running Vellen now. v0.1.49 tried to do this with WiX's util:CloseApplication, but that runs too late in the install sequence (after the "Validating install" step where the hang happens), so it couldn't help — the install still stalled when a previous Vellen was open. This replaces it with a custom action that force-closes Vellen before that validation step, so the upgrade proceeds on its own instead of hanging. Vellen autosaves continuously, so the forced close is safe.

Version 0.1.49

  • The app has a real bottom edge now. The sidebar list used to run straight off the window with nothing under it, so the bottom-left of the app "fell away" while the editor had its status bar. The sidebar now has its own footer that lines up with the editor's status bar — a continuous strip across the whole app — showing a live note and whiteboard count. Above it, a soft fade appears only while there's more to scroll, so the list dissolves into the footer mid-scroll and ends cleanly at the bottom. Adapts to light and dark automatically.
  • Note-less folders now show consistently after syncing. A folder that holds no notes (only images, attachments, or subfolders) shows dimmed in the tree. On a device that received that folder via sync, it wasn't appearing until the app was reopened — the sync refreshed the note list but never the folder list, and the file watcher is paused during sync. That's why such folders showed on the vault's origin device (e.g. your Mac) but not on one populated by sync (e.g. Windows). Every sync now refreshes the folder tree from disk, so folders look the same on every device.
  • Windows installer closes a running Vellen automatically. Installing or upgrading while Vellen was open stalled silently at "Validating install" because the running app's files were locked. The MSI now asks a running Vellen to close (and closes it if needed) before installing, so the upgrade completes on its own — no hang, no manual "close the app first," no reboot prompt.

Version 0.1.48

  • Google sign-in is resilient again on Windows. Through v0.1.44, desktop sign-in used a fixed loopback port (21847) and just worked. v0.1.45 replaced that with dynamic-port machinery — bind any free port, ask the backend which one, then ping and redirect to it — and it hard-failed sign-in whenever any link in that chain hiccuped, showing a "couldn't open a local sign-in listener" error even when the listener was fine. (v0.1.47 softened the health ping but still hard-failed if the port lookup came back empty; this removes that last hard-fail.) Sign-in now falls back to the default port if the lookup fails and treats the health ping as advisory — the app binds the port itself, and the browser reaches 127.0.0.1 directly for the real redirect. It still blocks only when a different program is positively answering on the port.

Version 0.1.47

  • Windows now ships as an MSI installer (.msi) instead of the NSIS -setup.exe. The NSIS bundler in the current build toolchain produces a corrupt installer that downloads fine but fails on launch ("Error launching installer"); the MSI is built from the same app and installs cleanly. Both formats are first-class for Tauri's auto-updater, so this costs nothing on the update roadmap. Note: users must stay on the format they installed with — standardizing on MSI keeps everyone on an auto-updatable installer.

Version 0.1.46

  • Google sign-in works when the whole preferred port range is blocked. On some Windows machines, Hyper-V/WSL reserve a large contiguous block of ports that swallowed the entire 21847–21947 range Vellen tried, so its local sign-in listener couldn't bind anywhere and sign-in failed with a "couldn't open port 21847" error. If that range is fully taken now, Vellen falls back to an OS-assigned free port (which can't be inside a reserved block) and points the Google redirect at it — so sign-in works regardless. Error messages also now report the actual port instead of always naming 21847.
  • Windows installer (.exe) builds reliably again. The release workflow installed dependencies with npm install, which let the Tauri CLI float to a newer version whose NSIS bundler produced a corrupt installer — it downloaded fine but failed on launch with "Error launching installer" (the .msi was unaffected). CI now uses npm ci, pinning the build toolchain to the lockfile so the Windows installer is reproducible from now on.
  • Wikilinks render cleanly again. With raw markdown hidden, a [[Note]] link could show a stray ] after the name and behave like an external link. The editor's markdown parser was mistaking the inner [Note] for a shortcut link and fighting the wikilink renderer over the same brackets. Wikilink brackets are now left to the wikilink renderer, so [[Note]] shows just the styled name and clicks through to the note.

Version 0.1.45

  • Images stop masquerading as notes on synced devices. When syncing (e.g. Google Drive on mobile), attachment files like images were being added to the note list — so a folder holding only images wasn't dimmed, and tapping an image opened its raw binary as gibberish text. Attachments are now kept out of the note list on the sync path too (matching local-folder behavior); they still sync to disk so notes can reference them. Folders that hold only images are correctly dimmed again.
  • Note names are safe to save on every OS. Every spot that turns a title, heading, or imported name into a filename now runs through one sanitizer. Beyond stripping illegal characters (which it already did, but inconsistently), it escapes Windows reserved device names — a note called "CON", "PRN", "NUL", "COM1"…"LPT9" couldn't be created on Windows at all — and trims leading/trailing dots and spaces that Windows silently mangles. Existing notes are untouched; this only applies when creating new names.
  • Dates use your local timezone, not UTC. "Today" was computed from UTC, so in the evening (the Americas) or the morning (Asia/Australia) a daily note could be dated a day off and today-based queries could quietly miss. Daily notes, the {{date}} template variable, today in queries, and the daily note's "is this today" navigation all now use your actual local date.
  • Google sign-in no longer depends on one fixed port. Sign-in uses a local loopback listener; if its port (21847) was taken or reserved by the OS — common on Windows with Hyper-V/WSL/Docker — sign-in couldn't start at all. The listener now falls back through a range of ports and sign-in uses whichever one actually bound. If it still can't open one, the error now explains the likely cause and points to folder-based sync (Dropbox/OneDrive/iCloud), which needs no listener. The browser clipper now discovers that port automatically too, so it keeps working on machines where 21847 is unavailable (re-save the clipper from Settings to pick up the update).
  • Hover actions across the whole sidebar. Smart folders and boards now show edit/delete icons on hover like regular folders do, and notes and whiteboards show a delete icon on hover — no need to right-click for the common actions.
  • Delete always confirms. Deleting a smart folder or a board now asks first (noting your notes aren't affected), matching the existing confirmation for folders and notes.
