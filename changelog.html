Vellen — What's new

Latest: version 1.0.21, September 9, 2026

Every version, what it changed, and what was wrong before it. Written plainly, on purpose: a notes app is something you trust with your thinking, and you should be able to see exactly what we fixed and when. Something not right? Write to admin@capitalcalcs.com, or use Settings → About → Report a problem inside Vellen.

Version 1.0.21September 9, 2026

  • What's new, on the website. Every release note from this file is now published at vellen.capitalcalcs.com/changelog.html, in the same words, with the release date — so you can see what changed, and what was wrong before it, without opening the app.
  • "Your Drive copy looked empty" is no longer said about a Drive that isn't. A Windows machine reported that sync had protected its notes because the Drive copy looked empty — while the Drive copy was intact. Two things could make Drive's file list come back as nothing without Drive ever saying so: a "successful" reply that wasn't Drive at all (a hotel or airport Wi-Fi sign-in page, a proxy) used to be read as an empty list, and Drive's own "this search was incomplete" flag was ignored. Both now stop the sync with a plain sentence — "Google Drive couldn't be read properly — a Wi-Fi sign-in page or a proxy may be in the way" — and nothing is compared, so nothing is judged. The same sign-in page at token-refresh time no longer reads as "your Google sign-in has expired" either. The protection message itself now says the Drive copy may simply have been unreadable just now, and to look before rebuilding.
  • Help explains inline code. The formatting list said backticks make "inline code" and left it there. It now says what that's for — a file name, a shortcut, a menu path, an exact phrase, anything to be read exactly as written — and that everything inside is taken literally, which is how to mention a piece of Markdown without triggering it.

Version 1.0.20September 7, 2026

  • Selecting a paragraph no longer paints two overlapping blocks. The line you're on has a faint tint that stops at the text; a selection across a wrapped paragraph is drawn the way every editor draws it, out to the edges of the writing area. Together they made a stepped block in two shades. While anything is selected, the selection is now the only highlight; the line tint returns when you click or move on.
  • Owners are never asked to register a trial. After updating on an iPhone that had already bought the unlock, a notice said the 14-day trial had been registered with the App Store — while About correctly showed the licence as owned. At launch the app asks the store and opens your last folder at the same time; when the folder won the race, the trial registration ran before the store had said "licensed". It now waits for the store's answer first (bounded, so an unreachable store still can't block a real trial), and the "registered" notice is only ever shown to someone actually on a trial.
  • New notes can take their folder's shape. A folder of like notes — every application, every project — tends to share the same properties, and a new note there used to start empty: open a neighbour, copy the names, blank the values. Now, when the other notes in a note's folder share properties it lacks, the Properties panel offers Add this folder's properties (3). One click adds the names with blank values — a checkbox unticked, a list empty — and never copies a value or touches one you already have; it adds only what's missing, so a note you started by hand catches up too. It reads only the notes beside this one (never a subfolder's or another folder's), and a folder with a table or board offers that table's columns. Never automatic: a note that should have no properties ignores it. Also in the command palette.

Version 1.0.19September 6, 2026

  • Edit ▸ Select All selects the note, not the whole app. On a Mac, picking Select All from the menu bar lit up everything — sidebar, tabs, panels and note together — because the menu item was the system's own action, aimed at the window rather than at what you were editing (⌘A on the keyboard never did this; the editor handles that itself). The item is now Vellen's: it selects all of the note under the cursor, or the text field you're typing in, or a whiteboard card's text — and with nothing focused, it selects nothing at all.
  • The calendar emoji is gone from previews too. A task's due date is written in the file as 📅 2026-10-24, and on Apple devices that emoji draws a calendar page reading "JUL 17" — a second, wrong date beside the real one. The editor has hidden it behind the app's own icon since 30 Aug, but linked mentions, search results and the published site's search still showed it. Previews now read "due 2026-10-24"; rendered notes — hover previews, embeds, whiteboard cards, exported pages and websites — draw the same icon the editor does. The file is unchanged.

Version 1.0.18September 5, 2026

  • The report that arrives after the restart. Diagnostics used to live only in memory, so a report made after reopening the app said "no errors recorded this session" — precisely when there was most to say. The last 60 events now carry across launches (labelled as an earlier session's), every message and stack trace is stripped of file paths before it is recorded rather than at one caller, and a save that fails while the app is quitting or closing is written down instead of being swallowed. Help's description of the report now matches it: the only path it shows is your notes folder's own location.
  • A key that missed the keychain no longer stays missed. If the system keychain didn't answer when a key was saved — locked, slow, or dismissed — the app used to keep that key in its own settings for the rest of the session without saying so. It now tells you once, offers "Try now", asks the keychain again on its own, and moves the key across the moment it answers. Google AI keys travel in a request header, not the address, so they can't appear in a log that quotes a URL.
  • The launch document tells the truth again. LAUNCH-READINESS's headline section was dated 8 Aug and quoted v0.1.95, 723 tests and a four-gate script; it now reads 5 Sep 2026 with v1.0.17, 1,405 tests, five gates, the audit's four tiers, and the decision that 1.0 is Apple and Microsoft with Google Play following in 1.x once Play Billing exists. The Mac App Store sandbox row is ticked (it was complete on 7 Aug and marked open), and rows exist for the in-app privacy link, the acknowledgements, phone update paths and the quit/background flush. README and MAINTENANCE name lint as a ship gate.
  • The parts nobody had tested. The website export's real code path now runs in tests — publish: false, a folder's own index.md as the home page, custom.css kept across re-exports, image copying, section links, the outline, the skipped count — instead of a look-alike the tests built for themselves; the build is a pure function the app and the tests share. The purchase flow (trial ended → read-only → buy → writable again) and the front door (welcome screen, the three ways in, an unreachable Drive, picking a known folder) have automated tests for the first time. No behaviour changed; what changed is what a regression can hide behind.
  • Faster on phones, larger websites, longer notes. Opening a folder, a background sync and the views list each checked files one at a time, waiting on every round trip; they now check several at once (5–10 s on a phone with thousands of notes, down to a fraction). A website export of a big folder no longer writes the entire navigation tree into every page — past 300 pages each page carries its own folder chain and the rest fills in when opened, so a 5,000-page site is megabytes, not gigabytes; the graph is laid out in short slices so the app stays responsive while exporting, and isn't included past 2,500 pages; search text is trimmed to 2 KB per page. In the editor, moving the cursor no longer rescans the whole note for tables, images, maths, diagrams and embeds — only an edit does — so arrow keys on a very long note are instant again.
  • The screens that show thousands of notes stay quick. The sidebar tree re-rendered every row on every change anywhere in the app (a dirty-flag flip in one note, a sync pulling 500); it now redraws only when the notes, folders or selection actually change (2,300 rows: 435 ms → 17 ms per change). A table draws its first 300 rows and offers "show 300 more" / "show all" instead of laying out every row on each keystroke in the filter bar, and it no longer re-runs on unrelated changes. The Tasks view remembers which notes hold which tasks and re-reads only the ones that changed, instead of every task note on every keystroke; it also waits for typing to pause. The graph stops drawing once the layout has settled — it used to redraw every frame forever, one stroke per link, which warmed laptops and drained phones — and skips measuring labels for notes off the screen.
  • Big folders open and search faster. Opening a folder of several thousand notes took seconds even from cache, because every note's broken links were re-checked against every other broken link in the folder; that work now scales with the note, not the folder (a 5,000-note test with three broken links per note: 8.9 s → 0.2 s), and the whole load notifies the sidebar once instead of once per note. The index cache — a startup shortcut, not a record — is no longer rewritten two seconds after every save (20 MB on a large folder, on a phone); it's written when the folder has been quiet for a while, and always before the app closes, switches folders or goes to the background. Search-as-you-type finds prefix matches by binary search instead of walking the whole vocabulary, and builds snippets only for the results it shows (a common word: 104 ms → 27 ms). Smart folders run each query once per change rather than on every sidebar render, and a version checkpoint reads its index once instead of twice.

Version 1.0.17September 4, 2026

  • The sidebar no longer scrolls sideways, and the app no longer shifts inside its window. The Graph, Tasks, Calendar and Ask AI rows were four pixels wider than the sidebar, which was enough for a horizontal scrollbar; the rows fit now. Separately, the page around the whole app could scroll by a few pixels whenever anything ran slightly taller than the window — so a click-drag on empty space nudged everything. The frame is fixed now; only the sidebar, editor and panels scroll.
  • One name for the thing your notes live in. The app said "vault" in some places and "notes folder" in others for the same folder; it now says notes folder everywhere you can read it (Help included). A round of small fixes with it: "New whiteboard" in the command palette (it said "canvas", the file extension); "Import from Evernote (.enex)…" opens the file picker straight away; the sidebar's ＋ makes a fresh note immediately, exactly as ⌘N does and as the Welcome note promises; Encryption drops its "(beta)" and a sentence written for testers; the Sync page's pointer to Encryption is one line; Unlock and Restore are disabled (with the reason shown) on a build with no store behind them; the Trash's "Delete forever" is a labelled button, not an ×; "Click" starts its sentence in the sidebar blurbs. On published websites: the outline no longer double-escapes "&" in headings, it sits below the note's own title instead of above it, the home page's links to pages with # or & in their names work, a sparsely linked site no longer labels every dot on the graph, "Remove this setup…" says so if the delete fails, and Help describes search results as a few words around the match, which is what they are.
  • Keyboard, screen readers, and the weight of a question. Right-click menus are real menus now: focus moves in when one opens, ↑/↓ and Home/End walk it, Enter picks, Escape closes and puts focus back where it was. Tabs are tabs — ←/→ switch, the × is a named button. Every dialog keeps Tab inside it, closes on Escape from anywhere, and returns focus when it goes; when one dialog sits on another, Escape closes the top one only. The system "reduce motion" setting now stills every animation, not just one spinner. The toast has two temperaments: a status fades as before, while an error — "your changes are NOT on disk" — stays until you close it, with its own × and a red edge, and is announced as an alert. Moving a note or whiteboard to the trash no longer asks first: it's recoverable, so the toast offers Undo instead (folders still ask — they carry more). The two heavy sync actions that asked nothing — Rebuild Drive backup and Disconnect — now do, and Rebuild says so when Drive isn't connected rather than spinning. Empty states: an empty Library invites the first note, an empty Graph explains itself (no notes, no notes matching the tag filter, or notes with no links between them yet), and a command search with no match says what to try.
  • Phones, boards and the words on the purchase screen. On a phone, the ⋯ menu now has Rename… and Move to folder… for the open note (moving was drag-only, which a finger can't do, and Help claimed the menu had it), and the note screen shows its title once instead of three times over a tab strip with a single tab in it. The purchase screen names the store you installed from — a Windows buyer saw "App Store record: none for this account yet" while their Microsoft Store trial was running — reads Microsoft's trial end date, and says 15 days on Windows where the Store enforces 15; Help says when that trial starts. Two error screens that showed a raw stack trace (Google sign-in failing, a folder that wouldn't open) now say what happened and what to try; the details go to Diagnostics. The licence screen no longer offers "Decline & quit" on iPhone and iPad, where it did nothing.
  • A better first ten minutes. The sidebar now leads with your notes — Library sits above Views, Smart folders and Tags — so a first run shows the note list instead of four feature blurbs. Settings → About gains a "Your notes are in …" row with the real folder path and a Show in Finder / Show in folder button; the Welcome note names the folder too, and a new notes folder announces where it went the moment it's made. "Get your notes" (the sign-in screen) has a Back link, and Escape and the Android back button leave it; it also says that nothing is copied until you choose a folder. On the App Store builds, the $0.00 sheet that registers your free trial is now announced before it appears and confirmed after — and Help and the Welcome note explain it. "New table" and "New board" on a folder that isn't set up yet speak plainly ("Set up “Projects” for tables", properties, not frontmatter or schema), keep the name you typed, skip the setup screen when there's nothing to propose, and close on Escape — as does the board editor. The palette's "New board" now makes the same kind of board the sidebar makes, and there's a "New table" command beside it.
  • Three fixes to the newest code. On a published website, a link to a section of another page — [[Note#Budget]] — now opens that page at that section instead of showing as "Not part of this published site" (while the target page's own "Mentioned in" list said otherwise). Exporting a site again to the same folder now removes the pages an earlier export wrote for notes that have since been marked publish: false, renamed or deleted, and images no longer used — so a note made private really does leave the site, as Help promised. Only files Vellen wrote are ever removed; your custom.css, custom.js and anything you added yourself are left alone. And a table or board whose folder schema carried a key with a trailing space (status : in YAML does that) no longer writes a second status line into a note when you edit the value: the app now writes to the spelling the note already has, blind to case and padding alike, and the schema drops the padding on load.
  • Ready for the store reviewers. iPhone, iPad and Android builds no longer check GitHub for newer versions — those installs update through their store, and Settings → About says so. Settings → About now links to the website, the privacy policy and support, and carries the open-source acknowledgements (every library, its licence, its copyright line). Help's trial topic points at the privacy policy too. On a phone, a view that crashes now costs you that view, not the app — the same safety net desktop has had — and the app-level recovery screen no longer offers a folder picker phones can't use. Two doors in the trial's read-only promise are closed: after the trial ends, a checkbox toggle and an edit in the Properties panel no longer rewrite the note. And the phone's note menu no longer offers Export and Print, which only ended in an error there.
  • Six security hardenings from the pre-customer audit. The browser clipper's local listener now accepts clips only from real browser extensions — a web page could previously reach it through a sandboxed frame and write notes into your vault (and discover that Vellen was running); the clipped page's address is validated before it's written into a note; and a clip that arrives while Vellen is in the background no longer yanks the app in front of what you're doing. Sync refuses file or folder names from Drive that would land outside your notes folder (a folder named .. could write files elsewhere on every synced device), and every path the app resolves is now checked against the vault boundary as a last line. An encrypted vault's remembered key moved into the system keychain alongside the AI keys and Drive token. Links in rendered content — AI answers, Help, whiteboard cards — open in your browser instead of replacing the app's window with the page. Exports and published sites only include images from inside the vault. And the app's own permissions were tightened: "open" is limited to web and mail links, and the folder-access grant only accepts a real, non-root folder.
  • Nine ways to lose words, closed. The pre-customer audit (4 Sep) traced every path where typed text could quietly vanish or a note could be replaced without asking. Switching notes with "protection paused" on now writes the last keystrokes first (the paused switch had been skipping the flush). Switching vaults — from the vault menu, the welcome cards, or Trash → restore — flushes every open note and waits for any running sync before letting go, so a sync that outlived the switch can no longer write the old vault's boards into the new one. A sync that pulls a note you're mid-edit on raises the conflict banner instead of letting your next autosave overwrite the other device; the same if your autosave landed while the sync ran. "Saved" now means the words that were written — keystrokes typed during a slow write stay marked unsaved until their own save lands, so a quit can't trust a stale flag. New note, rename and move onto a name that already exists open or refuse instead of replacing the existing file. A note deleted by another app or device while you have unsaved edits keeps its tab and its words, and saving brings it back. A preferences file that exists but can't be read makes boards and pins read-only for the session rather than "empty" — the empty version, saved later, used to mark every board deleted on every device. The same absent-vs-unreadable rule now protects version history's index. Named versions work on Android (they were failing silently), and every "the other version is saved first" promise — conflict banners, History → Restore, closing a conflicted tab — now refuses to overwrite if that safety copy could not actually be taken, "protection paused" or not. And ⌘Q on the Mac, plus backgrounding on a phone, flush autosaves before the app goes.

Version 1.0.16September 4, 2026

  • A new task line is ready to type into — no spacebar first. The checklist button and Enter both insert \- [ ] \ with its space, but on Mac and iOS the caret could end up on the wrong side of a line-ending space, so typed text landed between the brackets and the space — \- [ ]text\ — and no checkbox appeared until you pressed space yourself. Text typed right after the brackets now always lands after the space (and supplies one if it's somehow missing), so click the button and just type, hit Enter and just type. Pressing space there deliberately still means exactly what it says.
  • Selecting text no longer paints a phantom block at the editor's foot. On Mac and iOS, dragging a selection could also fill a solid slab of highlight over the empty space below the note — nowhere near the text. Two selection painters were on at once: the editor draws its own selection, and a stylesheet rule was forcing the browser's native one back on too; WebKit "helpfully" fills the gaps between blocks when native selection paints, hence the slab. One painter now: the drawn selection keeps its color, the native one stays off, and the find panel's own text fields keep a styled selection of their own. Chromium happened to hide the overlap entirely — which is why no test ever saw it — so the new test pins the mechanism (drawn layer visible, native transparent) rather than the pixels.
  • The website export finishes its 24 Aug polish list. Four smaller pieces, closing out the plan: a page with three or more sections opens with an "On this page" outline whose entries jump straight to their section (every heading is deep-linkable either way); \publish: false\ in a note's properties keeps that note out of the export entirely — no page, no search result, no dot on the graph, and the export message says how many stayed private; a wikilink that resolves to nothing now renders as an honest dotted stub that explains itself on hover, instead of quietly dressing up as italics; and the sidebar's folders fold — real collapsible groups, with only the current page's chain starting open on large sites, so two hundred notes still make a readable map. All of it static HTML and CSS, working from a double-clicked index.html like everything else.
  • Exported websites have a graph. The sidebar's new Graph button opens a map of the whole site: every page a dot sized by how connected it is, every link between notes a line. Hovering a dot lights up its neighborhood, clicking one opens that page, drag pans and scroll zooms, and the page you came from is marked. The layout is computed by the app's own graph engine at export time and shipped with the site — readers download a finished picture, not a physics engine, so it opens instantly, looks identical for everyone, and the site stays true to its no-server promise. Second of the Publish-parity items from the 24 Aug plan.
  • Exported websites can be searched. A box at the top of every page's sidebar searches the full text of the whole site as you type — pages whose title matches rank first, each result shows the line that matched, Enter opens the top one, Escape brings the navigation back. True to the export's one rule, the words ship inside the site itself (in the same site-data.js the link previews already read), so search works with no server anywhere: from a web host, a USB stick, or a double-clicked index.html alike. First of the remaining Publish-parity items from the 24 Aug plan; the graph view is next.

Version 1.0.15September 2, 2026

  • A folder's table & board setup can finally be removed. The only "Remove this setup" button lived on a screen the app could never show — the Help audit caught it. Now the folder's row under Boards or Tables offers Remove this setup… in its right-click menu. It warns first, counting exactly what goes: every view saved for that folder (tables and boards share one setup, so both go together) and the property types the folder learned. Notes are never touched — every file keeps its properties as written. The e2e stub also learned that removing a directory removes it: deleted fixtures used to resurrect on the next read, which made every "and now it's gone" flow untestable.
  • The Help got its second full line-by-line check. Every topic audited against what the app actually does. What changed: the Tables topic now covers the Note row, bulk editing several rows at once, that stray spaces join capitalisation as not-part-of-a-property's- name, and that a never-ticked checkbox counts as unchecked; two instructions pointing at a Remove this setup button you can't actually reach are gone; the setup dialog's type list no longer claims it guesses links; web capture's size and time limits are stated; the AI tasks note says the vault-wide sweep only happens with the whole vault selected; the trial topic tells Android users plainly that buying isn't ready there yet; and app-store installs are told updates come from the store.
  • Web capture can't be flooded or stalled. The 25 MB ceiling used to be checked before the download (against a size the server declares, and can lie about) and again after (too late — the memory is already spent). The limit is now enforced while the page arrives, chunk by chunk, and the whole download gets one minute of wall clock — a server that trickles forever is refused the same as one that floods.
  • A Microsoft Store install stops hearing about updates from GitHub. The tester notice could announce a new version before the Store's own rollout reached you — an update the app can't install anyway. A Store install now leaves updates to the Store (and Settings says so); sideloaded and tester builds keep the notice, which is who it's for.

Version 1.0.14September 1, 2026

  • A trailing space is not a second property. status : in a note's frontmatter yields a key with an invisible trailing space, which made a second property with an IDENTICAL label beside the real one — the same invisible-twin problem the capitalisation fix killed, one character wider. Edge whitespace now joins capitalisation as not-part-of-the-name: the spellings match as one property everywhere, the setup dialog and filter bar offer the clean word, and padded duplicates in an existing setup heal on load.
  • A leftover title in a folder's setup is cleaned up. title is reserved for the note's name, so a property by that name (from before the reservation) was dead weight that could never show; it is now removed when the folder loads, and leaves the file at the next save.
  • Big folders stop paying for every keystroke. Typing in the filter bar was recomputing the table's column list — a walk over every note's properties — on each keypress, defeating the cache built to prevent exactly that. Unnoticeable in a small folder; a 3,000-note folder will feel it.

Version 1.0.13August 31, 2026

  • A table shows the properties your notes actually have. A folder's table learned its columns once, when it was first set up, so a property you added to a note afterwards was invisible — you could even filter by it and still not see it, which is a filter you cannot check. Columns now come from the notes: add owner: to a note and the column is there. The Properties button lists everything the folder knows about, and unchecking one hides that column for this view. A property you never wanted is a column you can see and hide in a click, which is a much smaller problem than one you cannot find at all.
  • Properties you add later can be filtered on. A folder's table learned its properties once, when you first set it up, and had no way to hear about one you added afterwards — so a property written on Tuesday was missing from the filter list for ever, with nothing on screen admitting it existed. The property dropdown now also lists what it can see in your notes, under "In your notes — not set up yet", and choosing one adds it to the folder. Nothing is added on its own, which is still what keeps a typo from becoming a column, and a property with a fixed set of values arrives knowing the values already in use.
  • Status and status are the same property. A folder that had both spellings written in it showed the property twice in the filter list — identical labels, different results, no way to tell which was which. Capitalisation is no longer part of a property's identity: the two are matched as one, and filtering on it finds notes written either way. Your notes are left exactly as you wrote them — nothing rewrites a key in a file behind your back — and a property you set from the app is written back using the spelling that note already uses. A folder that already had both spellings in its setup — from before this landed — heals itself the next time you open it, keeping the values both spellings knew about.
  • One spelling per property, even before it's set up. A folder with Status: in some notes and status: in others — and no table setup yet — showed one merged column with half its cells blank, because the heading unified the spellings and the cells didn't. They agree now. The setup dialog was worse: it offered the same word twice, both ticked, and Create wrote both spellings into the folder's setup — the original duplicate-property bug coming back through the newest door. It proposes one, spelled the way most notes write it, and its type guessing judges both spellings as one property — so Priority: 1 in two notes and priority: high in a third reads as text, instead of as a number that flags the third note the moment you adopt it. And it no longer proposes an empty "tags" list (or anything else that's blank everywhere) on folders where nothing is tagged.
  • A property's type can be forgotten. The Properties panel's × drops a property back to plain text — useful when a list of values is wrong, or a date-ness was guessed from notes that only looked like dates. The column stays and your notes are never touched.
  • title belongs to the note's name, whatever the capitalisation. A frontmatter Title: line was half-in: offered for adoption as a property while a filter on it read the note's name. Every spelling of it now means the name — never a column of its own, never offered, filters and sorts on it read the name. And the Properties panel leads with a Note row, so a hidden Note column finally has a listed way back.
  • A box nobody ever ticked counts as unchecked. "Done is unchecked" used to match only notes that literally carried done: false — which nobody writes by hand — so an open-tasks view hid exactly the tasks never marked at all, the newest ones. A missing checkbox now counts as unchecked; "is checked" still requires a real tick, so nothing sneaks into "done".
  • The Calendar is a calendar before you've dated anything. Opening it on a new vault used to replace the month with a sentence explaining how to add a date — so the one screen that shows what the Calendar IS was the screen a new person never saw. The month, with today on it, is always there now; the hint sits above it and leaves as soon as anything has a date.
  • A saved view can't go quietly wrong over a spelling any more. The Status/status fix unified how values were read, but a view FILE could still name the spelling that got folded away — and everything that trusted the file's spelling missed silently: a saved filter matched nothing (the table just went blank), a sort did nothing, and a board collapsed every card into its "No value" column. Views now resolve their filters, sorts, and grouping to the real property the moment they load, wherever the spelling came from.
  • A column from an older saved view shows its values again. A view written before the Status/status fix could name the spelling that got folded away: the heading looked right while every cell under it was blank, and clicking one opened a plain text box instead of the property's own editor.
  • A filter written before the Status/status fix keeps its operators. A saved filter naming the spelling that got folded away quietly came back as plain text: the operator menu lost "is any of" and the value box stopped offering the values to choose between. Nothing errored, which is what made it hard to spot. Capitalisation is now irrelevant in the last place it still mattered.
  • No more empty Tags column on every folder. Vellen adds a tags entry to every note behind the scenes, so the new columns-from-your-notes rule was putting an all-empty Tags column on folders where nothing is tagged. A property has to actually be filled in somewhere before it earns a column — unless you set it up deliberately, which still shows it straight away.
  • Showing or hiding a column no longer saves your half-built filter. The Properties checkboxes save immediately by design — looking is not editing — but they were saving the whole working copy, unsaved filter and sort edits included. Same for the ×: forgetting a type mid-edit committed the edit. Both now touch only what they say they touch, and forgetting the type of a property that's currently hidden no longer wipes the view's saved column order.
  • The filter bar lets go of a forgotten type. After × dropped a select back to plain text, the bar could keep offering "is any of" on values the property no longer has — a condition that matches every row and could even be saved into the view that way. The bar now follows the folder's setup the moment it changes.
  • Bulk edit's "＋ New option…" can't erase anything. Pressing Enter with the box still empty used to mean "clear this property on every selected note" — twelve notes updated by an unfinished thought. It now asks you to type the option first and stands still.
  • Nothing your files say is lost on save. A table's setup and view files are rebuilt from what the app understands every time they're saved — so a field written by a NEWER Vellen was silently stripped the moment an older one touched the folder, and in a vault synced across devices that don't update in lockstep, sync then spread the stripped file everywhere. Fields this version has no name for now ride through every save untouched, and a file's version number is kept instead of being rewritten downwards.
  • When old duplicate spellings disagree about a property's type, the one that knows the values wins. Folding a ref/Ref pair used to keep whichever was written first — and if that was plain text, the other's list of values was dropped for good, flagging everything already written under them. A select that actually carries its values now survives the fold whichever order the pair was written in. (The spelling still comes from the first.)
  • "Local AI — nothing leaves this device" only says that when it's true. The line was decided by which provider was answering, so it went on promising that while your notes crossed the network to an Ollama server on another computer — which is the setup Vellen's own Help recommends for phones and tablets. It now names that machine instead: Local AI at 192.168.1.20 — no cloud provider.
  • A local AI address typed without http:// works. localhost:8080 was saved as written, which built requests that could never connect — and the privacy line treated the address as another machine. The http:// is added for you now. The backup box also stops calling that address an "AI key in plain text": it's a server address, and the warning that cries wolf teaches you to ignore the one that matters.
  • A settings backup can find your AI keys again. Keys moved into the system keychain, and the backup was still looking in the old place, so ticking "include my AI keys" saved a file with none in it and said otherwise. It reads them properly now, tells you how many went in, and a restored key works straight away instead of waiting for a restart.
  • Restoring a settings backup checks what it's restoring. A damaged or hand-edited backup file could plant entries for providers that don't exist (or blank keys that showed a provider as connected but never worked) — and count them as restored. Only real providers with real keys come back now.
  • A saved xAI key shows as connected. Settings listed the providers by hand and xAI had been left off, so the panel offered to set up an account that was already working — with Test key and Disconnect hidden. The list is derived from the providers themselves now.
  • A full pass over the Help. Every topic checked against what the app actually does. The corrections worth knowing about: bold that wrapped onto a second line was printing as literal ** and stealing the emphasis from the next phrase (24 places); the Views list left out Calendar and Tables; the AI privacy paragraph didn't mention that a question about tasks sends every unticked checkbox in the vault, or that recent chat turns travel with each follow-up; the encryption topic said an older copy of Vellen would pause rather than damage its notes, which is backwards; query blocks need the word query on the fence line, and the example didn't have it; and the trial topic said 14 days everywhere when Windows is 15, and named payment on stores that don't take it yet.
  • Help catches up with the tables rework and the published site. Two instructions were sending people to a delete button that no longer exists — a row under Boards or Tables is a folder now, and a view is deleted by the × on its own tab. The Tables topic is rewritten around how tables actually work: columns follow your notes, what the Properties button does, adopting a property from the filter bar, why a date has to be written 2026-08-27, and that capitalisation doesn't count. The website-export topic now describes what it has been shipping since v1.0.12 — "Mentioned in" backlinks, link previews, and the custom.css / custom.js you can theme it with.

Version 1.0.12August 30, 2026

  • Published sites say who links to a page. Every exported page now carries a "Mentioned in" list of the notes that link to it, each with the line the mention sits on, so you can tell what a link was about before clicking it. Plain HTML — no script — so it works on any host and from a double-clicked file alike.

The export message now says that re-exporting to the same place is how you update a site.

Moving from one folder's table to another's left the first folder's views — tabs, filters, sorts — on screen and live, while the app already believed you were somewhere else. Saving in that moment wrote the view you were looking at into the folder you had just arrived at, so a filter called "Blocked" set up for Applications could end up belonging to Projects. Nothing was ever global: the screen and the app briefly disagreed about which folder you were in, and a running sync could stretch that moment out indefinitely. A folder's table now starts clean when you arrive, and a view can only be written to the folder it was loaded from.
  • Boards and Tables in the sidebar list folders, not every saved view. One row per folder, named after the folder, opening that folder's original table or board — and every other way you've saved of reading that folder is a tab along the top of the screen it opens. The list used to name every saved view in the vault, alphabetically, so two views of one folder sat rows apart with a third folder's view between them and nothing to say which belonged where. A folder with more than one shows the count.
  • "Table view" on a folder menu opens a table. It used to open whatever that folder happened to have — so a folder whose only view was a board answered the request with the board, every time. A table is now selected if the folder has one and created if it doesn't, and the new table appears as its own tab you can rename or remove. Asking while that folder's board was already on screen also used to do nothing at all, because nothing about the screen had changed.
  • Opening a folder's table says that it is opening. While a folder's setup was being read the screen was blank, which looks exactly like a menu item that did nothing — and if a sync happened to be running, the read never started at all and the blank stayed. It reads the folder now whether or not a sync is in progress, re-reads when the sync finishes, and says "Opening…" in the meantime.
